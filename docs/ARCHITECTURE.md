# Sprawl — Architecture and Build Plan

Read `PRODUCT.md` first. This document covers how to build it.

---

## 1. Stack (keep it compact)

| Concern | Choice | Why |
|---|---|---|
| Shell | **Electron** (latest stable) | Desktop, local files |
| Build | **electron-vite** | One config for main, preload and renderer, with fast HMR |
| UI | **React 19 + TypeScript (strict)** | What current shadcn/ui (Tailwind v4) targets |
| State | **Zustand** | Small, no boilerplate |
| DB | **SQLite via `better-sqlite3`** (main process only) | Fast, synchronous, single file |
| Query layer | **Drizzle ORM** + `drizzle-kit` migrations | Typed, thin, no runtime bloat |
| Search | **SQLite FTS5** (built in) | No extra search library |
| UI components | **shadcn/ui** (Radix primitives, copied into `components/ui/`) | Accessible menus, dialogs, popovers and so on, owned in the repo |
| Styling | **Tailwind CSS v4** + shadcn's CSS-variable theme (zinc base, **dark only**) + `tw-animate-css` | All colors come from the theme variables in `globals.css` |
| Fonts | **`geist`**, **`@fontsource/sora`** (npm) | Geist (UI), Geist Mono (times, code, kbd) and Sora 600 (brand moments only) as `.woff2` files copied into `src/renderer/assets/fonts/` and bundled locally (DESIGN_SYSTEM §3) |
| Note editor | **BlockNote** (`@blocknote/core`, `@blocknote/react`, **`@blocknote/shadcn`**), lazy-loaded when the note panel first opens | A Notion-style editor that renders with our shadcn components and theme. **Do not use `@blocknote/xl-*` packages**, because their licenses are incompatible with MIT. |
| Markdown export | **`@blocknote/server-util`** (main process only) | Runs BlockNote's markdown conversion in Node, so export doesn't need the renderer |
| Drawings | **`@excalidraw/excalidraw`** | Lazy-loaded, only when a drawing opens |
| Canvas | **Hand-built**: DOM items inside one CSS-transformed layer | No canvas library needed |
| Icons | **`@tabler/icons-react`** | Large, consistent outline set, tree-shaken. Every icon Sprawl draws comes from Tabler. Stock shadcn files still import `lucide-react` for their few internal glyphs (check marks, chevrons, close X), so `components.json` keeps `iconLibrary: "lucide"`: the CLI only rewrites icons for its newer styles, not new-york, and with `tabler` set it would add files importing `lucide-react` without installing it. |
| Command palette | **shadcn `Command`** (cmdk) | |
| Toasts | **shadcn `Sonner`** | |
| Dates | **date-fns** + shadcn `Calendar` (react-day-picker) | |
| Zip (backup/export) | **fflate** | Small |
| IDs | **nanoid** | |
| Packaging | **electron-builder** | **Windows NSIS installer** for v1 (x64). Keep dmg/AppImage targets in the config but mark them unofficial and untested. |
| Validation | **zod** | IPC input validation in main, settings schema, import/export shapes, form values. Shared schemas in `src/shared/schemas.ts`. |
| Unit tests | **Vitest** (+ `@testing-library/react` for components) | Fast logic and component tests |
| E2E tests | **Playwright** (`@playwright/test`, Electron via `_electron.launch`) | Real app, real SQLite, temp vault per test |
| Lint | ESLint + Prettier | |

**Don't add:** Redux, any other component library (MUI, Mantine, Chakra and so on), CSS-in-JS, React Flow/tldraw/Konva, Prisma, an ORM other than Drizzle, or a separate search engine. Ask before adding any dependency over 50 KB gzipped that isn't listed here.

### shadcn/ui setup
- Run `npx shadcn@latest init` in the renderer with style **new-york**, base color **zinc**, CSS variables on, and alias `@/components`.
- **Dark only:** put the dark values directly in `:root` in `globals.css`, set `class="dark"` on `<html>`, and delete the light theme block. No theme toggle.
- Add only the components used: `button input textarea label separator tooltip dropdown-menu context-menu popover calendar command dialog alert-dialog sheet scroll-area switch resizable sonner badge kbd checkbox toggle-group select`.
- Sprawl-specific tokens (note colors, canvas dot color, due-chip states) are extra CSS variables in `globals.css` and are exposed to Tailwind through `@theme inline`, for example `bg-note-sand` and `text-due-overdue`. Never use raw hex in components.
- **Never edit anything in `components/ui/`.** Those files are generated by the shadcn CLI, may only be added or updated with `npx shadcn@latest add …`, and stay byte-for-byte stock.
  - To extend, restyle or combine them, **create a new component** in `components/` that imports from `components/ui/`. For example, `components/IconButton.tsx` wraps `ui/button` and `ui/tooltip`, and `components/DuePicker.tsx` wraps `ui/popover` and `ui/calendar`.
  - Theme changes go through CSS variables in `globals.css` only.
  - Extra variants go in the wrapper via `cva` and `cn()`, never by editing the ui file.
  - shadcn adds and updates always go in their own commit, with a message starting `chore(ui): shadcn add`, so any other change to `src/renderer/components/ui/**` stands out in review. ESLint ignores `components/ui/**`, because the stock files aren't written to our lint rules.

## 2. Processes

```
┌───────────────── main (Node) ─────────────────┐
│ db/ (better-sqlite3 + drizzle)                │
│ vault/ (paths, attachments, backup, export)   │
│ ipc/ (typed handlers)                         │
│ protocol: sprawl-file://  → attachments        │
│ reminders/ (scheduler) · tray · globalShortcut │
│ windows: main window + quick-capture window    │
└───────────────▲───────────────────────────────┘
                │ contextBridge (typed API only)
┌───────────────┴──── preload ──────────────────┐
│ window.sprawl = { notes, canvas, drawings,    │
│   log, search, files, settings, app }         │
└───────────────▲───────────────────────────────┘
┌───────────────┴──── renderer (React) ─────────┐
│ views/ canvas, list, note panel, log,         │
│ drawings, search, settings · stores/ (zustand)│
│ capture/ (separate entry for capture window)  │
└───────────────────────────────────────────────┘
```

**Windows app plumbing** (main process):
- **AppUserModelId**, which Windows needs for toast notifications: `app.setAppUserModelId('dev.sprawl.app')` in the packaged app, where the installer creates the Start-menu shortcut with the same ID. In dev (`!app.isPackaged`) use `process.execPath` instead, or toasts won't show.
- **Deep links:** `app.setAsDefaultProtocolClient('sprawl')` in the packaged app (the installer registers it too). `npm run dev` registers the dev build (`electron.exe` plus the app folder) so real toasts can be clicked while testing; `SPRAWL_NO_PROTOCOL=1` skips that. E2E runs never register. Links look like `sprawl://note/<id>` and `sprawl://list/due`.
- `app.requestSingleInstanceLock()`: a second launch (or a protocol activation from a toast) focuses the existing instance. Its `second-instance` handler reads any `sprawl://` URL from argv and routes it (`nav:open-note`, `nav:open-list-due`). The first instance also checks its own argv on startup.
- **No application menu:** `Menu.setApplicationMenu(null)`. Otherwise Electron's default menu takes Ctrl+0, Ctrl+= and Ctrl+- (zooming the whole UI instead of the canvas), Ctrl+R (reload) and Ctrl+Shift+I (devtools). The whole UI zooms only through the `textSize` setting: the renderer handles Ctrl+Shift+= / - / 0 and saves it, and main applies it with `webContents.setZoomFactor` to the main and capture windows (plus `zoomFactor` in their `webPreferences` at creation). Main also scales what it sizes in device-independent pixels: the title-bar overlay's height, the capture window's width and fitted height, and the view size it uses for a captured note's position. Electron already disables visual (pinch) zoom by default, so don't re-enable it. Register the canvas wheel listener with `{ passive: false }`, so it can `preventDefault()` the ctrl+wheel events a touchpad pinch sends.
- **Tray** (`main/tray.ts`): a `Tray` with `resources/tray.ico` (multi-size, from `brand/tray-source.svg`) and the menu from PRODUCT §3.8. It exists whenever Sprawl runs (not in E2E). Closing the main window hides it when "keep running" is on (`closeGuard`'s `hideInstead`; nothing needs saving, the renderer keeps running); otherwise, and after Quit, the window really closes and the app quits (the hidden capture window would otherwise keep it alive).
- **Start at login:** `app.setLoginItemSettings({ openAtLogin, path: process.execPath, args: ['--hidden'] })`, synced on startup and when the setting changes. Unpackaged, the args start with the app folder, so the login item runs the last `npm run build`. With `--hidden`, the app starts in the tray and no window is shown.
- **Quick capture window** (`main/captureWindow.ts`): a second `BrowserWindow` (frameless, `alwaysOnTop` at the `screen-saver` level so it shows over fullscreen apps, `skipTaskbar`, transparent background with rounded corners, 520 wide) created hidden once the main window has painted (`ready-to-show`, so it never slows the first paint, and it's always the app's second window). The global shortcut shows and focuses it, and blurring it or pressing Esc hides it. It has its own small renderer entry (`src/renderer/capture.html`) that uses the same preload, API and styles.
  - **Hiding without activating the main window:** when a focused window hides, Windows hands focus to the app's next window, which would bring the main window forward. Call `minimize()` and then `hide()` on the capture window, so focus goes back to the app the user was in (its opacity goes to 0 first, so the minimize doesn't animate). Restore it (un-minimize) before the next show. Check this by hand (tests/MANUAL.md).
  - Each show sends `capture:show { mode }` (the default mode), places it on the monitor under the pointer and focuses it. The renderer reports its card's height (`capture.setHeight`, clamped to 112–320). Blur hides it, except in E2E mode.
  - **The global shortcut** (`CaptureShortcut`): `globalShortcut.register` returning false means another app holds the combo; the old one is kept. While Settings records a new one, `system.pauseShortcut(true)` lets go of it so the keys reach the recorder. Not registered in E2E mode.
- **Reminder scheduler** (`services/reminders.ts`): on startup and after every write to notes or the canvas (and when the reminder settings change), show what's due and arm a single `setTimeout` for the soonest next thing (a reminder, an overdue nudge, the morning summary, the end of a pause), capped at 24h, then recomputed. It also re-checks on a 60s interval and on `powerMonitor` `resume` and `unlock-screen`, because timers drift or stop while the PC sleeps. Fired reminders set `reminded_at` so they never fire twice. As built (phase 6):
  - **Missed:** anything more than 2 minutes behind its time is late (Sprawl wasn't running, the PC slept, a pause). One late item shows as itself; two or more become one "While you were away" toast ("2 reminders · 1 now overdue") that opens the List view's Due tab.
  - **Overdue nudge:** reuses `reminded_at`, no extra column: a note with a reminder whose `reminded_at` is before its due moment (its time, or the end of its day) gets one toast when it becomes overdue, and `reminded_at` moves past the due moment. "At due time" reminders never nudge (the reminder already said it). Changing the due fields clears `reminded_at`, so both come back.
  - **Due reminders off** skips (marks) reminders as they come due, so turning it back on doesn't bring a burst. **A pause** (`notificationsPausedUntil`) holds them until it ends.
  - **Morning summary:** once a day at its time (or on the first check after it, on a later start), if anything is due today or overdue; the day it went out is the `morningSummarySentOn` setting.
  - On the first check after a vault opens, and when the timezone changes, every pending `remind_at` is re-derived from the wall-clock due fields.
  - The tray follows every check (overdue count in the tooltip, Pause/Resume).
- **Toasts** (`services/notify.ts`): use Electron `Notification` with a custom `toastXml` whose `launch` attribute is the deep link and whose `activationType="protocol"`. Clicking the toast then works even from Action Center after the app has restarted, not only while the toast is visible. A `click` handler routes the link too, in case Windows hands the click to the running app; toasts are kept referenced until they close. In E2E mode a `RecordingNotifier` keeps them instead.
- **"Notifications blocked" detection:** Electron has no API for this, so read the registry with `reg query` (child_process). Notifications are blocked if `HKCU\Software\Microsoft\Windows\CurrentVersion\PushNotifications` has `ToastEnabled = 0` (all apps off), or `HKCU\Software\Microsoft\Windows\CurrentVersion\Notifications\Settings\<AUMID>` has `Enabled = 0` (Sprawl off). A missing key means allowed.

**Security:** `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` and a strict CSP. External links open via `shell.openExternal`, and only `http`, `https` and `mailto` are allowed. The renderer never touches `fs` or the DB directly.

## 3. Vault on disk

```
Documents\Sprawl\          (user-chosen; default = app.getPath('documents') + '/Sprawl')
  sprawl.db                SQLite (WAL mode)
  attachments/
    2026/11/<nanoid>-<slugified-original-name>.png
  backups/
    sprawl-2026-11-24.zip  (last 7 kept)
```

- The DB uses `PRAGMA journal_mode=WAL; foreign_keys=ON; synchronous=NORMAL`.
- **Migrations:** `drizzle-kit generate` writes SQL from `db/schema.ts` into `db/migrations/` (the first one is `0000_init.sql`, drizzle-kit's numbering). Each file is imported with Vite's `?raw` in `db/migrations/index.ts`, so the SQL is bundled into main and there's no folder to ship in the asar. `db/client.ts` applies the ones newer than `PRAGMA user_version`, each in a transaction, and refuses a vault from a newer schema. The FTS5 table is hand-written at the end of `0000_init.sql`, since Drizzle can't express virtual tables.
- **Startup:** `SPRAWL_VAULT` wins (not remembered); otherwise the vault in `config.json` opens. If that folder no longer exists (deleted, unplugged drive), onboarding shows instead of silently recreating an empty vault there.
- **Changing the vault** (Settings → Change…) opens the chosen folder's vault, or creates an empty one there, after a confirm dialog. The old vault stays where it is; nothing is moved.
- Attachments are **copied** into the vault on drop or paste, and a SHA-256 hash is stored. When the hash already exists, the existing file is reused.
- Files are served to the renderer through a custom protocol, `sprawl-file://`, with two routes:
  - `sprawl-file://attachment/<attachmentId>`: looks up the path in the DB and streams the file. It only serves files inside the vault.
  - `sprawl-file://thumb/<drawingId>?v=<updated_at>`: serves the drawing's `thumb_png` blob as `image/png`. The `v` parameter busts the cache after each save.
- `app.getPath('userData')/config.json` holds the **machine settings**: `{ vaultPath, window: { x, y, width, height, maximized }, settings: { …machine keys } }`. Each field is validated on its own, so a bad field is dropped without losing the rest, and writes are atomic (temp file + rename). The window state is saved debounced while moving or resizing and immediately on close; a saved position is reused only if its title bar is still on a connected display. Everything else lives in the vault's `settings` table.

## 4. Data model (SQLite)

All IDs are nanoid text. Timestamps are integer ms since epoch (UTC), and day keys are `YYYY-MM-DD` in the user's local time.

```sql
-- notes ------------------------------------------------------------
CREATE TABLE notes (
  id           TEXT PRIMARY KEY,
  title        TEXT NOT NULL DEFAULT '',
  body_json    TEXT NOT NULL DEFAULT '[]',   -- BlockNote document (JSON)
  body_text    TEXT NOT NULL DEFAULT '',     -- plain text, derived on save (for FTS and card preview)
  color        TEXT NOT NULL DEFAULT 'stone',-- token name: stone|sand|sage|sky|lilac|rose
  due_day      TEXT,                         -- nullable; 'YYYY-MM-DD' local wall-clock date (stays the same if the timezone changes)
  due_time     TEXT,                         -- nullable; 'HH:mm' local wall-clock time; null = due "sometime that day"
  remind       TEXT NOT NULL DEFAULT 'none', -- none|at|15m|1h|morning|1d
  remind_at    INTEGER,                      -- ms UTC, derived from due_day/due_time + remind in the current timezone; null if none
  reminded_at  INTEGER,                      -- set when the reminder fires (never fire twice)
  done_at      INTEGER,                      -- nullable
  check_total  INTEGER NOT NULL DEFAULT 0,   -- derived on save
  check_done   INTEGER NOT NULL DEFAULT 0,   -- derived on save
  attach_count INTEGER NOT NULL DEFAULT 0,   -- derived on save: image and file blocks in the body
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  deleted_at   INTEGER                       -- soft delete (for undo); purge after 30 days
);

CREATE TABLE note_links (            -- external URLs attached to a note
  id        TEXT PRIMARY KEY,
  note_id   TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  url       TEXT NOT NULL,
  label     TEXT,
  position  INTEGER NOT NULL
);

CREATE TABLE refs (                  -- internal [[links]], derived on save
  from_note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  to_kind      TEXT NOT NULL,        -- 'note' | 'drawing'
  to_id        TEXT NOT NULL,
  PRIMARY KEY (from_note_id, to_kind, to_id)
);

-- drawings ---------------------------------------------------------
CREATE TABLE drawings (
  id            TEXT PRIMARY KEY,
  title         TEXT NOT NULL DEFAULT 'Untitled drawing',
  scene_json    TEXT NOT NULL,        -- { elements, appState (subset), files }
  thumb_png     BLOB,                 -- ~480px wide
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  deleted_at    INTEGER               -- soft delete (for undo); purged after 30 days, like notes
);

-- attachments ------------------------------------------------------
CREATE TABLE attachments (
  id          TEXT PRIMARY KEY,
  rel_path    TEXT NOT NULL,          -- relative to vault root
  orig_name   TEXT NOT NULL,
  mime        TEXT NOT NULL,
  size        INTEGER NOT NULL,
  sha256      TEXT NOT NULL UNIQUE,
  width       INTEGER, height INTEGER, -- images only
  created_at  INTEGER NOT NULL
);

-- canvas -----------------------------------------------------------
CREATE TABLE canvas_items (
  id          TEXT PRIMARY KEY,
  kind        TEXT NOT NULL,          -- 'note'|'drawing'|'image'|'link'   ('group' arrives in v0.2 via a migration)
  ref_id      TEXT,                   -- note/drawing/attachment id; null for link
  url         TEXT,                   -- kind='link'
  title       TEXT,                   -- kind='link' label
  x REAL NOT NULL, y REAL NOT NULL, w REAL NOT NULL, h REAL NOT NULL,
  z           INTEGER NOT NULL,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);
CREATE UNIQUE INDEX canvas_items_ref ON canvas_items(kind, ref_id) WHERE ref_id IS NOT NULL; -- at most one card per note/drawing/attachment
CREATE INDEX notes_remind ON notes(remind_at) WHERE reminded_at IS NULL AND done_at IS NULL AND deleted_at IS NULL;
CREATE INDEX notes_due ON notes(due_day, due_time) WHERE done_at IS NULL AND deleted_at IS NULL;

-- daily log --------------------------------------------------------
CREATE TABLE log_entries (
  id         TEXT PRIMARY KEY,
  day        TEXT NOT NULL,           -- 'YYYY-MM-DD' local
  at         INTEGER NOT NULL,        -- timestamp shown
  kind       TEXT NOT NULL,           -- 'done' | 'manual'
  text       TEXT NOT NULL DEFAULT '',-- manual: the entry text; done: a snapshot of the note title at done time
  note_id    TEXT REFERENCES notes(id) ON DELETE SET NULL, -- kind='done'; shows the live title while the note exists, the snapshot after it's purged
  created_at INTEGER NOT NULL
);
CREATE INDEX log_entries_day ON log_entries(day, at);

CREATE TABLE note_activity (          -- for "carried over"
  note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  day     TEXT NOT NULL,
  PRIMARY KEY (note_id, day)
);

-- misc -------------------------------------------------------------
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL); -- JSON values
-- vault keys (stored here): viewport {x,y,zoom}, showDone, snap, autoBackup, panelWidth,
--       listFilter {tab,colors,sort}, remindersOn, morningSummary {on, time}, notificationsPausedUntil,
--       morningSummarySentOn (the day it last went out), lastCaptureOffset (stagger for the next captured note)
-- machine keys (stored in config.json, not here): captureShortcut, captureDefaultMode, keepInTray, openAtLogin,
--       textSize (small | default | large | larger)
-- The settings service hides the split: settings.get/set route each key to the right store.

-- search -----------------------------------------------------------
CREATE VIRTUAL TABLE search_index USING fts5(
  kind UNINDEXED, ref_id UNINDEXED, title, body,
  tokenize = 'unicode61 remove_diacritics 2'
);
```

**Derived-on-save rules** (all in main, inside one transaction):
- `body_text`: walk the BlockNote JSON and join the inline text, adding a newline per block.
- `check_total` and `check_done`: count checklist blocks.
- `attach_count`: count image and file blocks.
- `refs`: collect the inline `[[link]]` nodes (a custom BlockNote inline content type `ref` with `{kind, id}`).
- `search_index`: upsert a row for the note (title, body_text plus link labels and URLs), for each drawing (its title plus Excalidraw text-element text), and for each manual log entry.
- `note_activity`: upsert `(note_id, today)` on every save.

**Mark done** is one transaction: set `done_at = now`, insert a `log_entries` row with `kind='done'` and the note title in `text`, update the FTS, and cancel any pending reminder. **Undo done** deletes that log entry, clears `done_at`, and re-arms the reminder if it's still in the future.
- As built (phase 5, `services/log.ts setNoteDone`): the reminder is cancelled by `done_at` itself (the `notes_remind` index and the scheduler skip done notes). Undo deletes the note's `done` entry whose `at` equals `done_at`. A reminder that came due while the note was done gets `reminded_at = now` on undo, so it doesn't fire late. Marking a done note done (or an open one not done) changes nothing; a deleted note can't be marked. `updated_at` and `note_activity` aren't touched: done isn't an edit. The FTS part arrives with the search index in phase 10.
- A done entry shows the note's live title and color while the note exists and isn't deleted; after that, the `text` snapshot (and `note_id` goes null when the note is purged).

`remind_at` is derived on every save that touches `due_day`, `due_time` or `remind`, by converting the local wall-clock date and time to UTC in the current timezone:
- `at` gives the due time; `15m` and `1h` subtract from it. All three need `due_time`. If `due_time` is cleared while one of them is set, `remind` resets to `none`.
- `morning` gives 09:00 on the due day, and `1d` gives 09:00 the day before.
- Changing any of these fields clears `reminded_at`. On startup, and when the timezone changes, every pending `remind_at` is recomputed.

**Due states** come from `due_day` and `due_time` against the local "now": overdue is after `due_time`, or after the end of `due_day` if there's no time; soon is 2 days or less away; later is everything else.

**Purge:** on launch, notes and drawings with `deleted_at` older than 30 days are deleted for good, in one transaction with their canvas items, refs and FTS rows. Attachments that no note body, canvas item or drawing points to any more are left on disk in v1.

## 5. IPC API (preload → main)

Every call is `ipcRenderer.invoke` (so the renderer sees promises) with zod-validated input in main. `ipc/register.ts` parses each input with its schema from `shared/schemas.ts`, throws `IpcInputError` (message prefixed `[invalid-input] <channel>`) on bad input, and only answers senders that are one of our windows. The types live in `src/shared/api.ts` and are imported by both sides.

```ts
interface SprawlAPI {
  app:      { getVaultInfo(): VaultInfo;                     // { path: string | null (null = onboarding), defaultPath }
              pickVaultFolder(): string | null;                 // native folder picker only; nothing is opened
              openVault(path: string): VaultInfo;               // open or create, remember, emit vault:changed
              openExternal(url: string): void };
  notes:    { list(q: NoteListQuery): NoteListRow[];            // List view: filter, sort, colors, text
              placeOnCanvas(id, at?: {x,y}): CanvasItem;
              get(id): Note; create(p: NewNote): Note; update(id, patch: NotePatch): Note;
              duplicate(id): Note;                              // list/panel duplicate (not placed on the canvas)
              setDone(id, done: boolean): Note; remove(id): void; restore(id): void;
              backlinks(id): NoteSummary[]; links: { add, update, remove, reorder } };
  canvas:   { load(): CanvasItem[]; apply(ops: CanvasOp[]): CanvasApplyResult; };   // batched, one transaction
  drawings: { list(): DrawingSummary[]; get(id): Drawing; create(title?): Drawing; duplicate(id): Drawing;
              placeOnCanvas(id, at?: {x,y}): CanvasItem;
              save(id, scene: string, thumb: Uint8Array): void; rename(id, t): void; remove(id): void; restore(id): void };
  files:    { importFromPaths(paths: string[]): Attachment[]; importFromBuffer(name, mime, data): Attachment;
              locate(id): Attachment | null };
  log:      { day(day: string): LogDay; addManual(day, text, at?): LogEntry;
              update(id, patch): LogEntry; remove(id): void; daysWithEntries(month: string): string[];
              carriedOver(day: string): NoteSummary[] };
  search:   { query(q: string, limit?: number): SearchResult[] };
  settings: { getAll(): Settings; get<K>(k: K): Settings[K]; set<K>(k: K, v: Settings[K]): void };
  on(event, listener): () => void;                              // main → renderer events (below); returns unsubscribe
  vault:    { exportMarkdown(dir?: string): string; exportNote(id: string): string | null; backupNow(): string };
  capture:  { submit(p: { mode: 'note' | 'log'; text: string }): { ok: true; noteId?: string };
              hide(): void };                                   // capture window only
  system:   { testNotification(): void; notificationStatus(): 'granted' | 'blocked';
              openNotificationSettings(): void;                 // ms-settings:notifications
              setShortcut(accel: string): { ok: boolean; conflict?: boolean };
              pauseNotifications(minutes: number): void };
}
```

**Canvas ops** (`CanvasOp`) are the unit of both persistence and undo. `canvas.apply` runs a whole batch in one transaction, so a note and its card are always created, deleted and restored together:
- `create`: a canvas item. For `kind: 'note'` it can carry a `note: NewNote` payload, and the note row is created in the same transaction (the canvas never makes a note without a card).
- `update`: position, size, z, or a link card's url and label.
- `delete`: removes the item. For a note or drawing card it also soft-deletes the note or drawing.
- `restore`: the inverse of `delete`. It re-inserts the item with its old id and clears `deleted_at`.
- `setColor` and `setDone`: note fields that appear in canvas undo (PRODUCT §3.1).
- `CanvasApplyResult` returns the created rows, so the renderer can replace its optimistic copies.
- The renderer picks the ids (nanoid) of new cards and notes, so its optimistic copy and the stored row share one id. An `update` or `delete` of a card that's already gone is a no-op, and any other failure rolls back the whole batch.
- `canvas.load()` returns each note card with a `note` field holding what the card shows of its note (`CardNote`: title, color, `preview` (the first 400 characters of `body_text`), `checkTotal`, `checkDone`, `attachCount`, `linkCount`, `dueDay` and `dueTime`). The cards of deleted notes are skipped.
- A `create`'s `NewNote` can carry `body` (plain text from a paste: one paragraph block per line, `db/derive.ts textToBody`) or `copyOf` (a canvas duplicate: main copies the source's body, derived counts, links and refs, not the due date or done state). `notes.duplicate` uses the same copy.
- `restore` refuses a card whose note or drawing was purged (the batch rolls back). `setColor` on a card that's gone is a no-op; on a non-note card it fails.
- Types live in `shared/types.ts` and the zod schemas in `shared/schemas.ts` (`canvasApplyInput`: 1–5,000 ops per batch). Phase 2 has `create`, `update` and `delete`, phase 3 `restore` and `setColor`, and phase 5 `setDone`.
- `setDone { id, done }` marks a note card's note done or not done through `services/log.ts setNoteDone` (the same transaction `notes.setDone` uses for notes without a card). A card that's gone is a no-op; another kind fails. Its inverse is `setDone` with the old state, so redo after undo writes a fresh log entry at the new time. `CardNote` carries `doneAt`, and `canvas.load()` returns done cards too: the renderer hides them unless "Show done" is on.
- **Notes API so far (phase 4):** `get` (the note with its `links` in order), `create`, `update`, `duplicate`, `remove`, `restore` and `links.{add, update, remove, reorder}`. The 30-day purge runs on every vault open (launch and switch), through `VaultService`'s `onOpen` hook.
  - `NotePatch` is `{ title?, color?, bodyJson?, dueDay?, dueTime?, remind? }`. A deleted note can't be updated. One transaction writes the patch and what's derived from it: a body gives `body_text` and the counts (`db/derive.ts deriveBody`); due fields are normalized (`shared/due.ts normalizeDue`: no day means no time and no reminder, and a time-based reminder without a time becomes `none`) and give `remind_at` (`deriveRemindAt`), and a change to them clears `reminded_at`. Every save, link changes included, upserts `note_activity` for today.
  - `bodyJson` must be a JSON array (at most 5 MB). `links.add` appends; `links.reorder(noteId, ids)` must list exactly the note's links. Link URLs are http, https or mailto only.
  - `shared/due.ts` holds the due logic both sides use: day keys, `remind_at`, due states and the chip and panel labels.
- **Daily log API (phase 5):** `log.day(day)` gives `{ day, entries }` in time order, each `LogEntry` with `note: { title, color } | null` for done entries. `addManual(day, text, at?)`: `at` defaults to now on today, or the current time of day on another day, and must fall on `day`. `update(id, { text?, time? })` takes the time as `HH:mm` on the entry's own day, so an entry never changes day. Only manual entries can be updated or removed. `daysWithEntries('YYYY-MM')`. `carriedOver(day)`: notes with `note_activity` on the day before, not deleted, and not done by the end of `day` (today that means still open; on a past day, still open then). Manual text is trimmed, 1–10,000 characters. `notes.setDone(id, done)` returns the note.
- **Injectable clock** (`services/clock.ts`): every service reads `now()` from one `Clock`, and so does the purge. In E2E mode, `setNow` fixes it and broadcasts `clock:changed { now }`, and the renderer's `clockNow()` (`stores/clockStore.ts`) uses that instead of `Date.now()`, so "today" agrees on both sides. The renderer marks `<html data-fixed-now>` so a test can wait for it.
- **Close handshake:** the window's first `close` is held (`main/closeGuard.ts`). Main sends `app:before-close`; the renderer runs every registered flush (`lib/flushes.ts`: the note autosave, the canvas batch, the viewport and the panel width) and answers `app.readyToClose()`. IPC from one window is handled in order, so the writes land before the window closes. A renderer that doesn't answer gets 2s. (The `beforeunload` flushes alone also passed the autosave test; the handshake makes the order explicit rather than relying on Chromium's timing.)

- **List, capture and system API (phase 6):**
  - `notes.list(query)`: `{ tab, colors, text, sort }` → `NoteListRow[]` (`services/noteList.ts`; the SQL builder is pure and unit-tested). Deleted notes never show. Open = not done; Due = not done with a due date, soonest first (a time before "sometime that day"); Done = by done time, newest first; All. The sort applies to Open and All. Colors are an `IN` list (none = all), the title filter a `LIKE` with `%` and `_` escaped. Ties go to the most recently created. Each row has `firstLine` (of `body_text`), the chip counts, the due fields, `doneAt`, the times and `onCanvas`.
  - `notes.overdueCount()` (the List badge and the tray tooltip) and `notes.placeOnCanvas(id, at?)`: a default-size card centered on `at` (snapped, on top), or on the middle of the last view (the saved viewport and the main window's size) when the renderer doesn't know it. A note that has a card keeps it. `Note` carries `onCanvas`.
  - `capture.submit({ mode, text })`, `capture.hide()`, `capture.setHeight(px)`: only the capture window may call them. A note capture runs in one transaction: the note (first line the title, the rest the body), its `!date` (with a time it also gets an "At due time" reminder, so "Pay rent !fri 10:00" reminds on Friday at 10:00), and its card near the middle of the last view, stepped 24px over 8 places (`lastCaptureOffset`). A log capture joins its lines into one manual entry. Then main sends `data:changed`.
  - `system.testNotification()`, `notificationStatus()`, `openNotificationSettings()`, `setShortcut(accel)` (registers, then saves; `{ ok: false, conflict: true }` when another app holds it), `pauseShortcut(paused)` and `pauseNotifications(minutes)` (0 resumes).
  - Shortcuts are Electron accelerators checked by `shared/accelerator.ts` (`Ctrl`, `Alt`, `Shift`, `Super` in that order, then one key; Ctrl, Alt or Super is required, so a shortcut never swallows typing).
  - Writes (`notes.*` changes, `canvas.apply`, `placeOnCanvas`, captures) re-check reminders and the tray in main afterwards. Settings that main acts on (`remindersOn`, `morningSummary`, `notificationsPausedUntil`, `captureShortcut`, `openAtLogin`) go through the settings service's `onChange`.

Main also sends these events to the renderer: `vault:changed` (after a vault switch), `nav:open-note` (from a notification click, tray or deep link), `nav:open-list-due` (from the morning summary click), `data:changed` (after a capture, so the main window's canvas, list and log refetch), `capture:show { mode }` (to the capture window), and `clock:changed` (E2E only, when a test fixes the clock). The main window subscribes to the `nav:*` and `data:changed` events before React renders (`lib/mainEvents.ts`), so a link routed as soon as the page loads isn't lost.

`!date` parsing for quick capture lives in `shared/parseCapture.ts` (pure function, unit-tested): `!today`, `!tomorrow`, weekday names (`!fri`, `!friday`; the next one, 1–7 days ahead, never today), `!12dec` and `!dec12` (also full month names; this year, or next year if already past; a 29 Feb goes to the next leap year), with an optional `HH:mm` after it. The token must start a word and end at a space, the end or punctuation; the first one that names a date counts, and anything else with a `!` stays as typed. A time that isn't one (`25:00`) stays in the text.

### Canvas implementation notes
- **One world layer** `div` with `transform: translate(x,y) scale(z)`. The items are absolutely positioned children in world coordinates.
- **Viewport culling:** only render the items whose bounds intersect the viewport plus a 200px margin. Keep a simple spatial bucket grid (512px cells) for fast lookups.
- **Drags** update a transient store at rAF rate and commit one `canvas.apply([...])` on pointerup. Never write to the DB per mouse move.
- **Text stays crisp:** apply zoom with scale. Below 40% zoom, cards render as simplified blocks (title only) to stay fast.
- **Undo history** (`stores/historyStore.ts`): in-memory stacks of inverse `CanvasOp[]` batches (max 200 each). Every recorded `canvas.apply` inverts its batch against the state just before it (`views/canvas/ops.ts invertOps`: create/restore ↔ delete, update ↔ the old values of the patched fields, setColor ↔ the old color). Undo applies the inverse and pushes *its* inverse onto redo, so undoing a note card's create soft-deletes the note and redo restores it (never re-creates it). A step keeps its id through undo and redo, so a toast's Undo (`undoStep`) still finds it; undoing a step that isn't the latest becomes a step of its own. The renderer keeps what deleted note cards showed, so a restore draws the card at once. History is cleared on a vault switch. Note body edits use BlockNote's own undo, not this. Title edits on the card aren't canvas ops either (one `notes.update` when editing ends).
- **Selection and gestures** (`stores/selectionStore.ts`, `useSelectGestures.ts`): the selection, the card being title-edited, the marquee, and the **transient rects** of a running move, resize or nudge. Cards draw their transient rect; nothing is written until `commitGesture` turns the changed rects into one recorded `update` batch (no DB write during a drag; unit-tested with a spy on `canvas.apply`). Pointer moves are folded to one per frame; a press becomes a drag after 3px. Arrow-key nudges collect until the key comes up. The board holds pointer capture during a press, so Chromium aims `dblclick` at the board: double-clicks hit-test `elementFromPoint` instead of trusting the target.
- **Done cards** stay in `items` (so undo and "Show done" bring them back) but leave the spatial grid, so culling, the marquee, select all and zoom to fit skip them (`isShown`, `shownItems()`). A card marked done with "Show done" off is in `leaving` for 180ms (the fade), then hides; the selection drops it. "Show done" is the `showDone` setting, toggled from the top bar or Settings.
- **Card heights** (`measure.ts`): a note card's stored `h` is a floor; one shared ResizeObserver records each rendered card's real height, used for marquee hits, resizes and the selection box.
- **Pointer events:** use pointer capture. Space held means temporary Hand mode. Wheel with ctrlKey (pinch) zooms, and wheel without it pans. The wheel listener is non-passive so it can `preventDefault()`.
- **Shortcuts** (`lib/shortcuts.ts`) match on `KeyboardEvent.code` plus modifiers, not `key`. So Shift+1 is `Digit1` with Shift (its `key` is `!`), and Ctrl+= also accepts `NumpadAdd`.
- The dotted background is a CSS `radial-gradient` on the viewport, with `background-position` and `background-size` driven by the pan and zoom.
- **Viewport math** (`views/canvas/Viewport.ts`): `screen = world × zoom + (x, y)`, in px from the canvas element's top-left corner. The `viewport` setting stores that `{ x, y, zoom }`.
- **The viewport bypasses React:** a store subscription writes the world transform, the dot grid and `data-x/y/zoom` (used by the E2E tests) straight to the DOM. Wheel and pointer input are folded into one viewport update per animation frame. `will-change: transform` is set only while the view moves and dropped 150ms after it stops, so text re-rasterizes crisply at the new zoom.
- **Culling** (`views/canvas/spatial.ts`, `ItemLayer.tsx`): the store keeps a `SpatialGrid` in step with its items. The item layer re-renders only when the set of visible ids changes. `useSimplified()` (zoom below 40%) drops cards to title-only with no shadow.
- **Zoom:** Ctrl+= / Ctrl+- and the pill step through fixed stops (10, 25, 33, 50, 67, 75, 90, 100, 110, 125, 150, 175, 200, 250, 300 and 400%) around the middle of the canvas, gliding over 180ms (`camera.ts`; a repeat steps from where the glide is heading). Ctrl+wheel is continuous (about 22% per mouse notch, finer for a pinch) and direct. Shift+1 fits every card (never past 100%, with 64px padding) over 240ms. A new note off screen or below 100% is brought into view the same way (`revealViewport`). All glides are instant with reduced motion; any direct pan or zoom cancels a glide.
- **Saving the viewport:** 400ms after it stops moving, plus on window blur, `beforeunload` and leaving the canvas view.
- **Dev seed:** with `npm run dev`, **Ctrl+Alt+Shift+S** on the canvas places 1,000 placeholder notes (a 40-column grid around the view center) in one `canvas.apply` batch (`views/canvas/devSeed.ts`). It's left out of production builds.

### Editor notes (BlockNote)
- Lazy-load the editor with `React.lazy` when the note panel first opens, to protect the 1.5s cold start. The canvas renders previews from `body_text` and doesn't need BlockNote.
- The schema lives in `shared/blocknoteSchema.ts`, so the renderer editor and main's `@blocknote/server-util` export use the same blocks.
- Custom schema: the default blocks minus anything not listed in PRODUCT §3.2, plus the inline content `ref` (renders as a pill, click → open) and an image block whose upload handler calls `files.importFromBuffer` and returns `sprawl-file://attachment/<id>`.
- `[[` triggers a suggestion menu built with BlockNote's `SuggestionMenuController` using `search.query`.
- Debounce saves by 500ms and flush on blur, on panel close and on `beforeunload`.
- **As built (phase 4, BlockNote 0.57):**
  - `@blocknote/shadcn` 0.57 renders its menus with its own copies of the shadcn components, built on Base UI (not Radix), so the app's Radix components can't be passed in. They use the same token classes (`bg-popover`, `text-muted-foreground`…), and `globals.css` has an `@source` for `@blocknote/shadcn/dist` so Tailwind generates them from our theme. `views/note/editor.css` maps BlockNote's `--bn-*` variables and block styles onto the tokens.
  - The schema has the text styles only (no text or background color). The slash menu is an allow-list of PRODUCT §3.2's blocks (image and file join in phase 7), the side menu is the drag handle alone (its menu: Delete), and the formatting toolbar drops text alignment, which isn't part of the note model.
  - The panel (and with it the date picker, select, menus and BlockNote) is lazy-loaded the first time a note opens. The renderer's main chunk is 574 kB (490 kB after phase 3; the rest is `react-resizable-panels`, date-fns and the chips).
  - The editor's `onChange` only records a serializer: `JSON.stringify(editor.document)` runs when the save does. A body equal to the last one main confirmed isn't sent.
  - When no menu is open, BlockNote's own Escape handling blurs the editor (and marks the key handled); the panel treats that as its Esc and steps back.
  - **Writing in a card** (`views/canvas/items/CardBody.tsx`, requested during phase 4) uses the same lazy `Editor` with `variant="card"`: `disableExtensions` turns off BlockNote's block shortcuts (`heading-`, `bullet-list-item-`, `numbered-list-item-`, `quote-block-`, `divider-block-shortcuts`, `code-block-keyboard-shortcuts`) but keeps `check-list-item-shortcuts`; the paste handler takes plain text as text; no slash menu, toolbar or side menu. One card at a time (`selectionStore.bodyEditing`). It ends when focus leaves the card's editor (checked after blur, ignoring a window that lost focus to another app). The canvas gestures skip presses inside it (and on a card's own buttons, `[data-card-action]`), and the wheel scrolls it while it can scroll.
  - **One note, two editors:** the note store holds a note by reference count (`acquire` / `release`), so the panel and a card can hold the same note; the last release saves and drops it. Every body edit records its editor as the live source and bumps `bodyRev`; the other editor copies the live document in once per frame (`replaceBlocks`, not reported back as an edit). A newly mounted editor starts from the live editor's document, or the latest body (`currentBody`); an editor that goes away hands its document to the store (`detachBody`), so nothing reads from a destroyed editor.

### Excalidraw notes
- Lazy import with `React.lazy`, so it doesn't load until a drawing opens.
- **No CDN:** by default Excalidraw loads its fonts from a CDN, which breaks the CSP and the no-network rule. Copy its font assets into the renderer build (`public/excalidraw-assets/`) and set `window.EXCALIDRAW_ASSET_PATH` to that local path before the lazy import.
- `theme="dark"`, with Excalidraw's background set to match the app's background variable. Use `UIOptions` to hide the canvas actions that don't apply, such as save to file (keep export image).
- `onChange` → debounce 1s → `exportToBlob({ mimeType: 'image/png', maxWidthOrHeight: 480 })` for the thumbnail → `drawings.save`.

## 9. Quality bar
- TypeScript strict, with no `any` in shared types.
- Every DB write goes through a service function. Multi-row changes use a transaction.
- Every IPC handler parses its input with a zod schema from `src/shared/schemas.ts`, and invalid input throws a typed error. Settings are read through a zod schema with defaults, so a bad or old value never crashes the app.
- No network calls at all, apart from the user clicking a link.

### 10.2 Unit and component tests (Vitest)
- **Main/services:** derive.ts (text, checklist counts, refs), the log's day math across timezones, DST and midnight, the done/undo-done transaction, the FTS index upkeep, attachment de-duplication by hash, the markdown export of a note with an image and a ref, `remind_at` derivation for every remind option, and the reminder scheduler (with a fake clock: the soonest is armed, fired ones aren't repeated, missed ones are summarized, and done cancels). These use a real `better-sqlite3` in-memory DB with the migrations applied.
- **Native module:** `better-sqlite3` (v13+) ships **N-API prebuilt binaries** in its npm package (`prebuilds/win32-x64.node`, with `"gypfile": false`). N-API is ABI-stable, so the same binary loads in plain Node (Vitest) and in Electron. There's **no rebuild step**: no `postinstall`, no `electron-builder install-app-deps`, and no build tools needed. (This was verified in phase 0 with Node 26 and Electron 45.)
  - It needs **npm ≥ 11**. Older npm ignores `"gypfile": false` and tries to compile with node-gyp, which fails without Visual Studio. `package.json` `engines` plus `.npmrc` `engine-strict=true` make an old npm fail with a clear message.
  - npm 11's install-script allowlist (`allowScripts` in `package.json`) denies better-sqlite3's implicit `node-gyp rebuild`.
  - Packaging (phase 12): set electron-builder's `npmRebuild: false`, and make sure the `.node` file is unpacked from the asar.
- **Shared:** `parseCapture` (every `!date` form, times, removing the token, ignoring a `!` that isn't a date) and the `notes.list` query builder (each filter, sort, the color filter and the due grouping).
- **Renderer logic:** viewport math (screen↔world, zoom around the cursor), canvas op inversion (undo/redo), spatial culling, the shortcut dispatcher, and due-state calculation.
- **Components** (`@testing-library/react` + jsdom): NoteCard chips, NoteRow, DuePicker (with time and remind), ColorSwatches, ShortcutRecorder and the log Entry.
- **zod schemas:** valid and invalid fixtures for every IPC input.

### 10.3 End-to-end tests (Playwright + Electron, on Windows)
- `fixtures.ts` builds the app once (`electron-vite build`). For each test it creates two temp dirs under `os.tmpdir()`, one for the vault and one for userData, and launches with `_electron.launch({ args: ['out/main/index.js'], env: { SPRAWL_E2E: '1', SPRAWL_USER_DATA: userDataDir, SPRAWL_VAULT: vaultDir } })`. Both dirs are deleted afterwards (retry the delete, because Windows can briefly lock the SQLite files).
- **Environment variables** (read in main before `app` is ready):
  - `SPRAWL_USER_DATA`: calls `app.setPath('userData', …)`. Tests never touch your real `config.json`. And because Electron's single-instance lock is keyed on the userData folder, tests can run while your own copy of Sprawl is open.
  - `SPRAWL_VAULT`: use this vault and skip onboarding. `vault.spec.ts` leaves it unset, so it sees the real first-run flow inside its own temp userData.
  - `SPRAWL_E2E`: turns on E2E mode (below).
- **E2E mode** (`SPRAWL_E2E=1`) registers test-only hooks. They live on a main-process global (`globalThis.__sprawlTest`, `ipc/testHooks.ts`) that Playwright calls through `app.evaluate`, not on IPC channels, so nothing test-only is reachable from a renderer:
  - `setNow(ms)` fixes the injectable clock, so day, log and reminder tests are deterministic. The fixture's `setNow(app, page, ms)` also waits for the renderer to follow (`clock:changed`).
  - `setNow` also runs a reminder check, so advancing the clock is enough to fire what's due.
  - `notifications()` returns the notifications that *would* have been shown. In E2E mode `notify.ts` records instead of calling the real `Notification`, so tests don't spam the desktop and stay reliable.
  - `triggerCapture()` opens the capture window as if the global shortcut was pressed (and tells it the fixed clock). Real global shortcuts aren't registered in tests. `captureVisible()` says whether it's shown.
  - `openLink(url)` routes a `sprawl://` link as if a toast was clicked; `checkReminders()` runs a check; `trayState()` is what the tray would show.
  - The fixture's helpers (`notifications`, `openLink`, `openCapture`, `captureVisible`, `trayState`) wrap these. `openCapture` returns the capture window's page and watches its console too.
  - The tray and start-at-login are disabled in E2E mode, and `keepInTray` is forced off, so closing the window quits the app (otherwise `autosave.spec.ts` and `relaunch.spec.ts` would hang). The capture window doesn't hide on blur.
  - The capture window is the app's second `BrowserWindow`: specs that reach for the main window in main pick it by title (the capture window's is "Sprawl quick capture" from the start), not `getAllWindows()[0]`.
  - The protocol registration (`setAsDefaultProtocolClient`) is skipped, so tests don't change your machine's `sprawl://` handler.
- **Console check:** the fixture fails a test on any console error or warning, except the ones in `tests/e2e/known-warnings.ts`. That list is only for third-party libraries (BlockNote, Excalidraw, React dev notices), and each entry has a comment saying why it's there.
- Tests select elements with `data-testid` attributes. Every interactive element named in UI_SPEC gets one, such as `canvas`, `note-card`, `list-row`, `note-panel-title`, `log-entry` and `capture-input`.
- Run with `workers: 1` (Electron plus SQLite on Windows is more reliable serially), `retries: 1`, and `trace: 'retain-on-failure'`.

- **Closing:** Playwright's `app.close()` quits without firing the window's `close` event. To test close-time saves, call `BrowserWindow.close()` through `app.evaluate` and wait for the app's `close` event.
- **No visual screenshot tests.** They're too brittle to be worth it. Visual polish is checked by hand against UI_SPEC in phase 12.

### 10.4 Manual test checklist (Windows only, things automation can't cover)
Kept in `tests/MANUAL.md`, and run before each tagged release:
- The real global shortcut opens capture from Explorer, a browser and a fullscreen app.
- After saving or closing a capture, focus goes back to the app you were in, and the Sprawl main window doesn't come forward.
- Real Windows toasts appear with the Sprawl icon and name, and clicking one opens the right note (with the app in the tray **and** with the window open). Clicking an older toast from Action Center after restarting Sprawl also opens the right note.
- Turning Sprawl's notifications off in Windows Settings shows the "blocked" warning in Settings, and turning them back on clears it.
- Focus Assist / Do Not Disturb on: toasts are held by Windows, with no errors in the app.
- Sleep the PC through a reminder time and wake it: the reminder fires within 60s, or appears in the "while you were away" summary.
- Start at login: reboot and the app is in the tray with no window shown.
- Install, upgrade over the previous version, and uninstall with the NSIS installer. The vault survives all three.
- High-DPI: 125% and 150% display scaling look crisp; moving the window between monitors with different scaling works.
- Pen and touch on a touchscreen laptop, if available: pan, zoom and drawing in Excalidraw.

### 10.6 CI
